Windows 上的截图软件我换过不少，能留下来的没几个。劝退我的原因基本就三类：功能太少、UI 发卡、后台常驻太重。前两个还能忍，第三个是真受不了——就截个图而已，有必要常年占着我几百 MB 内存吗。

截图吧是这段时间换过来的，用了一阵子，目前没换回去的打算。

https://github.com/1003129155/jietuba

## 三类劝退，它一个都没踩

先说清楚我挑截图工具的三条线，不然"好用"两个字没意义。

| 劝退类型 | 具体长什么样 | 截图吧 |
|---|---|---|
| 功能少 | 截完只能画个框，长截图没有，OCR 让你自己开网页 | 长截图 / OCR / 钉图 / GIF / 扫码 / PDF 导出都在一个程序里 |
| UI 卡 | 选区跟手慢半拍，标注重绘掉帧，多屏不同缩放直接错位 | 选区走独立合成层，多屏混合 DPI 无缝截图 |
| 占用高 | 为了一个偶尔才用的功能常驻几百 MB | 作者 README 写的是常驻十几 MB 甚至几 MB 级别 |

第三条我没拿任务管理器认真测过，只是体感上它属于"你不会注意到它开着"的那类。这个数字你信 README 就好，别信我的感觉。

## 它凭什么让我留下

### 功能密度高，但不是堆功能

一句话概括：把截图这件事的前前后后都接住了。

- **截图**：区域、窗口、智能窗口识别（含 UI Automation 控件级）、多屏混合 DPI、鼠标指针可以画进图里
- **长截图**：上下左右四个方向都能滚动拼接，算法走 Rust 写的 `longstitch`
- **标注**：笔、矩形、椭圆、箭头（9 种杆身和箭头样式）、文字、自动递增编号、荧光笔、马赛克、聚光灯、橡皮擦
- **OCR**：PP-OCRv6 的 det/rec 小模型，跟着程序包走，**本地跑**，中英日
- **钉图**：截图钉在屏幕最前，还能继续标注、缩放、再 OCR、翻译
- **GIF 录制**：录屏 + 录制过程中直接画，导出 GIF 或视频
- **扫码**：框选一下，图里所有二维码 / 条码一次读完
- **导出**：多种编码图片 + 高质量 PDF

长截图这块我没做极限测试，横向拼接这种场景我也基本用不上，所以作者说的"毫秒级精准拼接"我不背书。但我日常竖向滚的长图，没拼歪过。

### 底层是 Rust 干的，不是纯 Python 糊的

这点是我决定认真用下去的原因之一。

界面是 PySide6，但图像处理、剪贴板操作、OCR 这几个容易拖后腿的部分是 Rust 实现，以 wheel 的形式发布：`j-gif`（GIF 编码）、`j-stitch`（长图拼接）、`j-clipboard`（剪贴板底层）、`j-ppocr`（PP-OCR 识别）。OCR 推理跑在原生线程，不阻塞 UI。

换句话说，它是 Python 的壳、Rust 的骨头。很多号称轻量的 Python 工具做不到这点。

### 翻译是唯一要联网的功能

除了翻译，其余全部本地运行，无数据收集、无偷偷联网。翻译也是你主动用才调，服务商你自己选：DeepL / Google / Azure / Amazon / 百度 / DeepSeek / 自定义 OpenAI 兼容接口（Ollama、LM Studio 这类都能接）。

## 一开始让我膈应的地方：它集成了剪贴板

这个是必须单独说一节的，因为我一开始是真的不想用。

我偏好干净一点的工具，剪贴板历史这种东西听着就臃肿——我这人连 Ditto 都没装。打开截图吧发现它自带一整套剪贴板管理，第一反应是"又来了"。

用下来的结论是：它没因为塞了这个功能就变重。

而且它做的方式有点意思——不只是自己截的图，**你复制的任何文本、图片、文件、HTML 都会自动进同一份剪贴板历史**。可以分组、收藏、搜索，有独立的三栏管理窗口，文本条目支持 CSV 导入导出。

最关键的一条：**历史记录里的任何一张图，都能一键"钉"回屏幕最前面**，随时拿来对照、缩放、继续标注、重新 OCR。

这就是它 README 里说的"截图 ⇄ 剪贴板 ⇄ 钉图"三向互通。听起来像宣传语，实际用起来确实省事：截完的图不用另存，复制过的东西不会丢，需要对照的时候从历史里翻出来钉着就行。

至于嫌烦的人——历史窗口是快捷键调出来的，不是常驻糊在屏幕上，不主动用就看不见。

## 装上就能用

不用装 Python，不用装 Rust，OCR 模型已经在包里。

1. 打开 [Releases 页](https://github.com/1003129155/jietuba/releases/latest)，按机器下载 `-x64.zip` 或 `-arm64.zip` 结尾的包
2. **整个压缩包解压**，保持 `jietuba_pp.exe` 和同级的 `models/` 目录在一起（模型缺了 OCR 就用不了）
3. 双击 `jietuba_pp.exe`

> [!WARNING] 未签名
> 程序没有做数字签名，浏览器下载后 Windows 大概率弹 SmartScreen。点"更多信息" → "仍要运行"即可。介意这点的自己权衡。

首次启动有个 6 页的引导向导，会把截图、剪贴板这几个主要热键带你设一遍，建议别跳过。

## 几个注意点

- **只有 Windows**（x64 和 ARM64），没有 macOS / Linux 版
- **免安装 zip，没有安装程序**，升级要自己下新包覆盖，也不会自动更新到最新版（它只做版本检查提示）
- **翻译要联网**，其余全本地
- 我写这篇时的最新版本是 2.0.10（2026-09-26），项目更新挺勤的，装之前看一眼 Releases

## 适合谁

适合：

- Windows 用户，截图频率不低
- 需要长截图、本地 OCR、钉图对照这类"截图之外"的能力
- 受不了工具常驻吃资源
- 想要剪贴板历史，但不想再单独装一个 Ditto

不适合：

- macOS / Linux 用户（没有）
- 只想按一下快捷键截个图、其他一概不要的人——它的功能面板对你来说会显得多

## 我的判断

我不敢说它是"最强"的截图工具，功能多不等于强，很多全能型工具最后都死在臃肿上。

但截图吧难得的地方在于：功能给得很足，重量却没跟着涨。这跟我之前换掉的那一批正好反过来。

剪贴板那部分我到现在也说不上"喜欢"，只能说它没拖累主体体验，而钉图 + 剪贴板打通之后确实省了几步操作。这算是我对它的唯一保留意见。

除此之外，用了一阵子没找到换回去的理由——对我来说这已经是很高的评价了。
